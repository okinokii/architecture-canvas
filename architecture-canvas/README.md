# Architecture Canvas

HTML-доска для визуализации архитектуры и подготовки запроса к Qwen 3.8 с поддержкой изображений. Рисование и экспорт живут в `index.html` (без зависимостей, офлайн); общая логика вынесена в `core.js`, а `mcp-server.js` превращает схему в MCP-инструменты для AI-агентов.

Открыть онлайн: https://okinokii.github.io/architecture-canvas/ . Или локально: двойным кликом по `index.html` (интернет не нужен).

## Как использовать

1. Откройте `index.html` в браузере (можно просто двойным кликом — интернет не нужен).
2. На холсте уже лежит заготовка типовой системы: клиенты → CDN/WAF → API Gateway → сервисы (Auth, Core API, Worker, Media) → PostgreSQL, Redis, Kafka, Object Storage + Observability.
3. Рисуйте поверх неё:
   - карандаш, линия, стрелка, прямоугольник, эллипс, текст, заметка;
   - готовые блоки из панели справа: клик по палитре, клик по холсту, редактор с полями «Название» и «Описание». Блок появляется только после **ОК**; **Отмена** ничего не добавляет, после добавления включается инструмент «Выбор» (`V`);
   - блоки заготовки можно тянуть инструментом «Выбор» — они переносятся в ваш слой вместе со связанными стрелками, а исходный элемент заготовки скрывается (состояние сохраняется в autosave и JSON);
   - при перетаскивании любого блока привязанные стрелки тянутся за ним: ближний конец едет вместе с блоком, дальний остаётся на соседнем блоке — связь не рвётся;
   - чтобы сделать из текстовой метки фигуру — выберите инструмент **«▣ Фигура»** (`F`), укажите форму в панели справа (прямоугольник или эллипс) и кликните по метке; повторный клик снимает рамку;
   - двойной клик по метке — изменить текст и описание; ластик, выбор/перемещение, панорама и масштаб колесом мыши.
4. Нажмите **«Экспорт PNG»** — изображение сохранится в файле `architecture-canvas.png`.
5. Нажмите **«Запрос для Qwen»** — выберите один из 5 форматов импорта и скопируйте текст.
6. В Qwen прикрепите PNG (для форматов `combo` и `png`) и вставьте скопированный запрос. Для текстовых форматов картинка не нужна.

Кнопка **«Пакет»** сразу сохраняет 4 файла: PNG, `architecture.mmd`, `architecture-schema.json` и готовый запрос.

## Дополнительно

- `Вписать` — показать всю схему целиком.
- `💾 Сохранить JSON` в правой панели и `📂 Импорт` на верхней панели — сохранить и восстановить пользовательский слой вместе со списком перенесённых из заготовки элементов.
- `Очистить мой слой` — убрать всё нарисованное, оставив заготовку.
- `Ctrl+Z` / `Ctrl+Y` — отмена/повтор, `Ctrl+S` — экспорт PNG, `Del` — удалить выбранный элемент.
- Горячие клавиши инструментов: `V`, `P`, `L`, `A`, `R`, `E`, `T`, `N`, `F`, `H`, `D`; пробел — временная панорама.

## Пресеты и сценарии

Кнопка **«🏛 Пресеты»** на верхней панели открывает окно с 29 шаблонами и фильтром «Категория»: **Архитектуры** (21) и **Процессы и события** (8).

### Архитектуры (21)

| Пресет | Что показывает |
|---|---|
| `layered` | Слоистый монолит: Браузер → Controller → Service → Repository → PostgreSQL |
| `mvc` | Model / View / Controller с серверным рендерингом |
| `microservices` | API Gateway, независимые сервисы, PostgreSQL/Redis/Kafka |
| `event-driven` | Producer → Kafka → Audit / Notify / Projection → хранилища |
| `cqrs` | Command API → Event Store → Event Bus → Projector → Read Model → Query API |
| `hexagonal` | Ports & Adapters: адаптеры → порты → ядро → инфраструктура |
| `serverless` | API Gateway → Lambda → DynamoDB/S3/EventBridge → Worker |
| `modular-monolith` | Модули в одном процессе + транзакционный outbox |
| `clean` | Чистая архитектура: адаптеры → use case/entity → порты → инфраструктура |
| `bff` | Отдельные BFF для web и mobile, общие IAM и хранилища |
| `streaming` | CDC/IoT → Kafka → Flink → OLAP/поиск/алерты (Kappa) |
| `microfrontend` | App Shell + Module Federation + Design System/Auth SDK |
| `service-mesh` | Envoy sidecar, mTLS, IAM/SPIRE и OpenTelemetry |
| `data-lake` | Лямбда-архитектура: сырые события → Kafka/Flink и S3/Spark → OLAP/BI |
| `ml-serving` | Feature Store → обучение → Model Registry → Inference API + контроль дрейфа |
| `rag-chat` | Вопрос → embedder → векторная БД → LLM → ответ + трассировка |
| `iot` | Датчики → MQTT → правила и stream → Timeseries DB / алерты / дашборд |
| `ecommerce` | Каталог и корзина → заказ → оплата и остатки → Kafka → уведомления |
| `multi-region` | CDN + GSLB → два региона со своими БД, репликация и общий SLO |
| `strangler` | Фасад и правила маршрутизации: постепенный уход от монолита |
| `observability` | health-check, демоны-экспортеры → Prometheus/Loki → Grafana/Alertmanager |

### Процессы и события (8)

Каждый сценарий — логическая/событийная диаграмма вида «сообщение или событие → реакция в инструменте → результат», с подписями на связях и легендой типов.

| Пресет | Что показывает |
|---|---|
| `flow-message` | Входящее сообщение → классификация → обработчик/БД → ответ и аудит |
| `flow-webhook` | Webhook оплаты → шина событий → заказ, остатки, уведомление |
| `flow-saga` | Оркестратор Saga → шаги заказа → компенсации (release/refund) и журнал |
| `flow-outbox` | Команда → БД + outbox в одной транзакции → relay → Kafka → read model |
| `flow-retry-dlq` | Consumer → retry с backoff → DLQ → алерт → разбор → replay |
| `flow-incident` | Health-check/SLO → алерт дежурному → логи и фикс → выкатка → постмортем |
| `flow-cicd` | Push → CI/тесты → registry → деплой → health-check/smoke → релиз |
| `flow-cron` | Cron → демон → отчёт и письмо → метрики задачи |

Кнопки **«Заменить слой»** и **«Добавить»**: пресет превращается в настоящие блоки, зоны, стрелки с типами и подписями и заметки. Доска сама отключает заготовку и вписывает схему в экран. Экспорт Mermaid/JSON и валидация работают без дополнительных действий; все 29 пресетов проходят проверку без ошибок.

По трём пресетам реализованы рабочие сервисы в `../preset-services`: `layered-monolith`, `event-driven`, `cqrs`. У каждого есть `schema.json`, код, тесты и README.

## Блоки и примеры в правой панели

Палитра «Блоки архитектуры» содержит 20 типов: базовые (`service`, `gateway`, `client`, `db`, `cache`, `queue`, `storage`, `external`) и практические (`monitoring` — health-check и метрики, `daemon`, `worker`, `scheduler` — cron, `balancer`, `auth`, `analytics`, `ci`, `config`, `firewall`, `ai`, `vector`). Клик по блоку открывает редактор; отмена ничего не добавляет.

Секция **«Примеры блоков и событий»** вставляет готовые фрагменты в центр экрана:

- **💓 Health-check** — сервис и мониторинг со связью `GET /healthz → 200 OK`;
- **🧵 Демон → очередь → воркер** — задания `EVT`, результат `DATA` в БД;
- **📨 Сообщение → реакция → результат** — входящее событие, вызов инструмента, ответ;
- **🔁 Retry + DLQ + алерт** — обработка ошибок и повторная подача;
- **⏰ Cron → демону → отчёт** — периодическая задача и уведомление;
- **🔐 Запрос → JWT → решение** — проверка токена и журнал аудита.

Вставленный фрагмент состоит из настоящих блоков, привязанных стрелок с подписями и типами и заметки-легенды; его можно двигать, редактировать и отменять через `Ctrl+Z`.

## Конструктор кубиков, связей и пространств для ИИ

Кнопка **«🧱 Конструктор»** на верхней панели (или **«Открыть конструктор»** в правой) открывает окно с четырьмя вкладками:

- **🗂 Пространства** — название, ширина и высота зоны; зоны можно добавлять, изменять и удалять.
- **🧊 Кубики** — `id`, название, описание/технология, тип из палитры, пространство и цвет. Новый куб автоматически раскладывается внутри выбранной зоны; при смене `id` или названия привязанные стрелки обновляются.
- **🔗 Связи** — кубы «откуда» и «куда», подпись события и тип связи (`SYNC`, `ASYNC`, `DATA`, `AUTH`, `EVT`, `DEP`). Стрелка сразу привязана к блокам; можно снять галочку «привязать», чтобы оставить висячий конец для проверки валидацией.
- **🤖 Инструкция для ИИ** — произвольный текст заказчика. Он сохраняется в браузере, добавляется в конец любого варианта запроса, в JSON (`instruction`), в текстовое описание и в набор файлов Gist.

Все изменения идут через `snapshot()`, поэтому `Ctrl+Z` / `Ctrl+Y` работают так же, как при рисовании. Кнопки внизу окна сразу открывают C4-валидацию или готовый запрос для Qwen — конструктор не требует ручного экспорта.

Тот же сценарий доступен через MCP: инструмент `build_schema` принимает `spaces`, `cubes`, `links`, `notes`, `instruction` и возвращает `schema`, `mermaid`, `validation` и `prompt`.

## Диктовка текста в блоки

В редакторе блока есть кнопки **«🎤 Название»** и **«🎤 Описание»**:

- нажмите нужную кнопку (или `Ctrl+M` / `Ctrl+Shift+M`) и говорите — распознанный текст добавляется прямо в поле;
- intermediate-results показываются по мере речи, финальный текст остаётся после паузы;
- повторное нажатие останавливает запись, закрытие редактора тоже её останавливает;
- язык выбирается в списке в окне редактора или в панели **«Диктовка в блоки»** — 18 языков (русский, украинский, английский, немецкий, французский, испанский, итальянский, польский, португальский, турецкий, чешский, нидерландский, китайский, японский, корейский, арабский, хинди); выбор запоминается и синхронизируется между обоими списками; язык можно менять прямо во время записи — распознавание перезапустится.

Технически используется Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`). Работает в Chrome и Edge; в Safari/Firefox или старых сборках кнопка покажет сообщение о неподдержке. Обычная Chrome-реализация распознаёт речь через интернет, поэтому офлайн-режим доски на рисунок не влияет, но для диктовки нужна сеть и разрешение на микрофон.

## Планшеты и S Pen

Доска адаптирована для Android-планшетов и стилуса Samsung S Pen:

- **Раскладка**: на экранах уже 900 px инструменты превращаются в горизонтальную панель внизу, правая панель настроек становится выдвижной (`☰` в шапке), кнопки и цветовые образцы увеличиваются на сенсорных устройствах (`pointer: coarse`), учитываются безопасные зоны (`safe-area-inset`). На планшете в альбомной ориентации сохраняется привычная трёхколоночная раскладка, но элементы управления тоже крупнее.
- **Жесты**: один палец рисует выбранным инструментом (в настройках можно переключить на панораму), два пальца — одновременное масштабирование и панорама с сохранением точки под жестом. В правом нижнем углу холста есть крупные кнопки `− / ⤢ / +`.
- **S Pen**: распознаётся по `pointerType: 'pen'`. Нажим меняет толщину мазка (0,35×…1,65× от базовой), наклон делает его «каллиграфическим» (одна сторона шире). Используются `getCoalescedEvents()` — сохраняются все промежуточные точки высокочастотного опроса. Боковая кнопка пера — временная панорама, ластик пера (`button=5`) — удаление элементов движением. Текущий нажим и наклон показываются в статус-баре.
- **Отсечение ладони**: включено по умолчанию — касания пальцами игнорируются, пока перо опущено или недавно перемещалось (900 мс). Все настройки (отсечение ладони, нажим/наклон, режим касания, масштаб интерфейса) сохраняются в `localStorage`.
- **Масштаб интерфейса**: в разделе «Масштаб интерфейса» ползунок и кнопки `−/+` меняют размер панелей, кнопок и шрифтов от 80 % до 180 %, не затрагивая масштаб схемы. «Авто под экран» включён по умолчанию: на сенсорном экране от 1200 px (например, Galaxy Tab S8 Ultra) размер автоматически становится 115–125 %. Ключи — `archcanvas.uiScale` и `archcanvas.uiAutoScale`.
- **APK**: нативная WebView-обёртка для Android лежит в `../android`; в Actions можно собрать APK. Диктовка в WebView зависит от движка, в Chrome/Edge она работает через Web Speech API.
- **Производительность**: DPR ограничен 2,5, точки мазка прореживаются по расстоянию и изменению нажима, поэтому длинные линии с пера не раздувают схему.

Старые схемы без давления рисуются как обычные линии — формат совместим. При сохранении данных нажим и наклон просто хранятся в точках `p/tx/ty` и переносятся при перемещении мазка.

## Автосохранение и версии

- Всё, что вы рисуете, автоматически сохраняется в `localStorage` через 500 мс после изменения.
- Раз в минуту создаётся контрольная точка; вручную её можно сделать кнопкой **«＋ Версия»**. Хранится до 30 последних версий.
- Список версий в панели справа: **«Восстановить»**, **«Удалить»**, **«⬇ История»** (выгружает историю в JSON).
- После перезагрузки страницы схема восстанавливается автоматически. **«💾 Сохранить JSON»** в правой панели и **«📂 Импорт»** на верхней панели остаются для обмена между браузерами и для Git.

## C4-валидация

Кнопка **«🔎 Проверить схему»** запускает мягкий линтер из `core.js`:

- ошибки: блок без названия, повторяющийся id, связь на несуществующий блок;
- предупреждения: нет зон/контейнеров, нет заголовка, связь без подписи, меньше двух блоков;
- советы: не указана технология, блок вне зоны, нет легенды.

Результат показывается в окне с текстовым списком и JSON. Это эвристика, а не замена экспертному анализу C4.

## GitHub

В панели **«GitHub Gist»** введите personal access token с правом `gist` и нажмите **«Создать»** или **«Обновить»**. В gist попадают:

`architecture-schema.json`, `architecture.mmd`, `qwen-prompt.txt`, `c4-validation.txt`, `README.md` и `architecture-canvas.json` (полное состояние доски, которое можно загрузить обратно через «📂 JSON»).

ID созданного gist запоминается в браузере. Токен никуда не отправляется, кроме `api.github.com`, и не попадает в выгружаемые файлы. Gist создаётся приватным; поставьте галочку `public` только через MCP-инструмент `push_gist`.

## AI-интеграция

Панель **«AI (OpenAI-совместимый API)»** отправляет в модель:

1. готовый `combo`-промпт (JSON > Mermaid > изображение);
2. PNG схемы в формате `data:image/png;base64,…` вторым блоком `content`.

Подойдёт DashScope/Qwen-VL, OpenAI, локальный сервер с совместимым `/v1/chat/completions`. Укажите endpoint, модель и ключ — ответ появится в окне, его можно скопировать. Ключ хранится только в текущей странице; endpoint и модель запоминаются в `localStorage`.

## MCP-сервер

`mcp-server.js` — минимальный MCP-сервер на чистом Node.js (без npm-зависимостей), stdio JSON-RPC. Подробное описание с примерами — в [`MCP.md`](MCP.md). Инструменты:

| Инструмент | Что делает |
|---|---|
| `build_schema` | конструктор по спискам `spaces` / `cubes` / `links`: возвращает `schema`, Mermaid, C4-валидацию и промпт; `instruction` попадает в JSON и промпт |
| `import_project` | анализирует каталог готового проекта и возвращает готовую схему (nodes/edges/zones/notes), Mermaid и C4-валидацию; результат импортируется в доску кнопкой «📂 Импорт» |
| `read_schema` | читает выгруженный `architecture-schema.json`, возвращает схему и счётчики |
| `validate_c4` | мягкая C4-валидация + Mermaid |
| `export_mermaid` | Mermaid с опциональной пометкой о валидации |
| `build_ai_prompt` | промпт `combo` / `png` / `mermaid` / `json` / `prose` |
| `make_gist_files` | файлы для Gist |
| `push_gist` | создать/обновить Gist (токен из аргумента или `GITHUB_TOKEN`) |
| `list_presets` | список из 29 пресетов с категориями (`architecture` / `process`), тегами и счётчиками |
| `get_preset` | полное описание пресета + JSON-схема + C4-валидация |
| `preset_export` | экспорт пресета в `schema` / `mermaid` / `prompt` / `gist` / `all` |

Запуск и подключение:

```json
{
  "mcpServers": {
    "architecture-canvas": {
      "command": "node",
      "args": ["C:/Users/daniel/Documents/Проект по умолчанию/architecture-canvas/mcp-server.js"]
    }
  }
}
```

Для GitHub-инструмента задайте `GITHUB_TOKEN` в окружении сервера. Три основных потока:

1. **Конструктор по описанию:** агент вызывает `build_schema` со списками `spaces` / `cubes` / `links` и текстом `instruction` → получает схему, Mermaid, валидацию и готовый промпт. Схему можно загрузить на доску через «📂 Импорт».
2. **Импорт проекта:** агент вызывает `import_project` с путём к репозиторию → получает схему и Mermaid → сохраняет JSON (аргумент `output`) → пользователь открывает доску и нажимает «📂 Импорт». Доска сама раскладывает блоки по зонам и строит связи.
3. **Анализ нарисованной схемы:** нарисовали на доске → «Пакет» сохранил `architecture-schema.json` → агент через MCP читает схему, проверяет её, строит промпт и при необходимости публикует Gist.

## Какой формат импорта лучше

| Формат | Что получает модель | Результат теста извлечения (14 сущностей / 15 связей) | Когда использовать |
|---|---|---|---|
| `combo` (рекомендуется) | PNG + Mermaid + JSON | 14/14 и 15/15, подписи точные | Основной вариант для Qwen с vision: картинка для компоновки, текст как источник истины |
| `json` | только JSON-схема | 14/14 и 15/15 | Максимально детерминированный разбор, меньше всего галлюцинаций |
| `mermaid` | только Mermaid | 14/14 и 15/15, но подписи содержали `Название<br/>Описание` | Когда важна визуальная/logic-структура и компактность; в промпт добавлено правило разделять `<br/>` |
| `prose` | словесный список | 14/14 и 15/15 | Когда модели лучше даётся естественный язык, без разметки |
| `png` | только изображение | Не проверялось напрямую; по бенчмаркам VLM по SADU: сложные/пересекающиеся и «обратные» стрелки и подписи связей распознаются заметно хуже | Только если нет возможности передать текст |

**Вывод:** PNG сам по себе не оптимален как единственный канал — он теряет точность на подписях и направлении стрелок. Лучший вариант: **изображение + Mermaid + JSON одновременно**, с явным приоритетом данных `JSON > Mermaid > картинка`, определением entity/relation и требованием сначала вернуть строгое JSON-извлечение, а уже потом анализ. Это реализовано в формате `combo`.

## Сквозной тест

На доске был нарисован маленький сервис (3 блока, 2 стрелки, заметка с эндпоинтами), после чего по выгруженному `schema.json` реализован `../simple-service` — все 5 тестов проходят.

Второй этап — по 7 пресетам из `presets.js` автоматически сгенерированы `schema.json` и реализованы три сервиса в `../preset-services` (`layered-monolith`, `event-driven`, `cqrs`). Тесты: 5 + 6 + 4 = 15, все зелёные. Пресет `cqrs`, загруженный на доску, выгрузился в JSON с 8 nodes / 8 edges и 3 зонами, в Mermaid — с 2 асинхронными связями.

В ходе теста исправлено:
- появилось второе поле редактора — можно менять описание блока, а не только название;
- устранены коллизии id у блоков, добавленных подряд (`u1`, `u2`, …);
- Mermaid больше не теряет символы `()` и `<>` в подписях;
- синтетические pointer-события больше не падают без `setPointerCapture`;
- статус после очистки слоя больше не остаётся устаревшим;
- блоки по умолчанию стали текстовыми метками с редактированием при создании, а обрамление в прямоугольник/эллипс вынесено в отдельный инструмент `F`.
